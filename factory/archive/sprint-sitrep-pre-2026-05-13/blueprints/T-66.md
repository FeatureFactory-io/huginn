# Blueprint T-66 — GJLR-AGENT: GjallarhornAgent + sitrep_service steps

## Design
Implement `GjallarhornAgent` with `create_plan` and `execute_single_step`.
Also implements `build_narrative_plan_steps` in `sitrep_service.py` (SVC-01–03).
`process_user_message` must `raise NotImplementedError` — do not implement it.

`create_plan` wraps `ExecutionPlan` + `PlanStep` creation in `transaction.atomic()`,
then calls `execute_plan.delay(plan_id)` (lazy import to avoid circular deps).

`execute_single_step` assembles 4 system cache-blocks (PROMPT + Playbook + FRAGOs + SA),
calls `LLM.generate_with_tools`, dispatches tool calls via `ToolExecutor`, persists
`step.result` and `step.outcome_assessment`, marks step `completed`.

## Risks
- Lazy import `from gjallarhorn.tasks.plan_tasks import execute_plan` inside `create_plan` body — avoids circular import (tasks → agent → tasks).
- `execute_plan` task body is a stub in T-66 (the real task is T-67); `create_plan` just calls `.delay()`. In tests, Celery eager mode runs whatever is registered.
- `_build_system_blocks` calls `tool_executor.execute('get_active_playbook', ...)` — if tool returns `{success:False}`, use empty string for that block rather than raising.
- SSE publish points: `# TODO(chat-milestone): publish plan_started` — comment only, no implementation.
