# Blueprint T-65a — GJLR-TOOLS part 1: ToolExecutor + data tools

## Design
Implement `ToolExecutor` (the permission-aware envelope dispatcher) and the two
data tools (`list_commits`, `get_contributor_activity`). These are the most
exercised read tools and establish the envelope contract for T-65b.

`ToolExecutor.execute(tool_name, **kwargs)` never raises — all errors become
`{"success": False, "result": None, "error": "..."}`. Write tools are blocked
by name membership in `WRITE_TOOLS` frozenset.

## Interfaces
```python
class ToolExecutor:
    WRITE_TOOLS = frozenset({'create_frago', 'extend_sitawareness',
                             'create_jira_issue', 'approve_decision'})
    def __init__(self, user, project): ...
    def register(self, name: str, fn: callable) -> None: ...
    def execute(self, tool_name: str, **kwargs) -> dict: ...  # always returns envelope
```
`list_commits(project_id, from_dt, to_dt, limit=200)` queries `ingestion.Increment`
where `kind='commit'` and `committed_at ∈ [from_dt, to_dt)`.

## Risks
- Check exact field name on `Increment` model (`kind`, `committed_at`, `author_email`) before writing queries — read `ingestion/models/` first.
- Cross-project contamination: every query MUST filter on `project_id`.
- `get_contributor_activity` aggregates — use Django `values('author_email').annotate(Count)`.
